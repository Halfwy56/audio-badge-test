# Audio QA перед выгрузкой

## Порядок
1. `python tools/audiokit.py check <файлы> --json` — по одному JSON на файл.
2. Для каждого файла смотри `status`:
   - `fail` — не выгружать; сообщить причину из `issues`.
   - `warn` — выгрузить, но в отчёте назвать вероятную **аппаратную** причину (таблица ниже).
   - `ok` — выгружать.
3. Выгрузка: `python tools/audiokit.py upload <файл>`. Успех — только при `"sha256_ok": true` и коде 0.
4. Итоговый отчёт: таблица файл / статус / метрики / действие. Без выдуманных метрик — только из JSON.

## Как читать предупреждения
| Признак | Порог | Вероятная причина на бейдже | Что предложить |
|---|---|---|---|
| `clipped_ratio` | > 0.1 % | слишком большой gain PDM/PGA, крик рядом с микрофоном | снизить gain на 6 дБ, включить AGC с лимитером |
| `silence_ratio` | > 90 % | микрофон не инициализирован, неверный PDM clock, сработал VAD/mute | проверить логи прошивки; сравнить с тестовым тоном |
| `dc_offset` | > 2 % FS | отсутствует HPF после децимации PDM, дефект АЦП | HPF ~80 Гц в прошивке или на backend |
| `sample_rate` ∉ {16000, 48000} | — | неверная конфигурация децимации/кодека | сверить с полем codec в BLE-сервисе |
| пиковый уровень < −30 dBFS при нормальной речи | — | микрофон закрыт одеждой/корпусом | проверить акустический порт |

## Ограничения (сообщать пользователю)
- Анализируется только первый канал и только 16-бит PCM WAV. Opus/OGG сначала декодировать (`ffmpeg -i x.opus -ar 16000 -ac 1 x.wav`).
- Детектор тишины энергетический: шум цеха ≈ речь по энергии, поэтому `silence_ratio` в шуме занижен. Это не VAD.
- Метрики не оценивают разборчивость речи (SNR/WER). Для этого нужен прогон ASR.
