# Audio QA перед выгрузкой

## Порядок
1. `python tools/audiokit.py check <файлы> --json` — по одному JSON на файл. Инструмент не падает на плохом входе:
   не-WAV, обрезанный или отсутствующий файл приходит как `status: fail` с причиной в `issues`.
2. Для каждого файла смотри `status`:
   - `fail` — не выгружать; сообщить причину из `issues`.
   - `warn` — выгрузить, но в отчёте назвать вероятную **аппаратную** причину (таблица ниже).
   - `ok` — выгружать.
3. Выгрузка: `python tools/audiokit.py upload <файлы> --check` — одной командой на все файлы; `--check` сам
   пропускает `fail`. Успех — код 0 и строка `"sha256_ok": true` на каждый файл. Код 2 — хотя бы один файл
   не принят; причина в выводе (`backend unreachable`, `giving up after N retries`, `skipped (check: fail)`).
4. Итоговый отчёт: таблица файл / статус / метрики / действие. Без выдуманных метрик — только из JSON.

## Как читать предупреждения
Все пороги — константы в начале `tools/audiokit.py`; таблица повторяет их, а не задаёт.

| Признак в JSON | Порог | Вероятная причина на бейдже | Что предложить |
|---|---|---|---|
| `clipped_ratio` | > 0.1 % | слишком большой gain PDM/PGA, крик рядом с микрофоном | снизить gain на 6 дБ, включить AGC с лимитером |
| `silence_ratio` | > 90 % | микрофон не инициализирован, неверный PDM clock, сработал VAD/mute | проверить логи прошивки; сравнить с тестовым тоном |
| `peak_dbfs` (при `silence_ratio` ≤ 90 %) | < −30 dBFS | микрофон закрыт одеждой/корпусом, забит акустический порт | проверить акустический порт, крепление бейджа |
| `dc_offset` | > 2 % FS | отсутствует HPF после децимации PDM, дефект АЦП | HPF ~80 Гц в прошивке или на backend |
| `sample_rate` ∉ {16000, 48000} | — | неверная конфигурация децимации/кодека | сверить с полем codec в BLE-сервисе |
| `issues`: «ожидается 16 бит» | — | другой формат экспорта/кодек | конвертировать ffmpeg в s16le |

## Как читать выгрузку
- `resume from offset N` — backend уже имел N байт (прошлый обрыв), докачка.
- `connection lost (...), resume from N` — обрыв во время передачи, клиент переспросил offset; норма.
- `sha256 mismatch, server reset the upload — retrying from scratch` — на backend лежал битый `.part`;
  сервер его удалил, клиент один раз отправил файл заново. Если повторилось — файл меняется во время выгрузки
  или backend неисправен; сообщить пользователю.
- `stored` с суффиксом `.<8 hex>` в имени — на backend уже был другой файл с таким именем; оригинал не затёрт.

## Ограничения (сообщать пользователю)
- Анализируется только первый канал и только 16-бит PCM WAV. Opus/OGG сначала декодировать
  (`ffmpeg -i x.opus -ar 16000 -ac 1 x.wav`).
- Детектор тишины энергетический: шум цеха ≈ речь по энергии, поэтому `silence_ratio` в шуме занижен. Это не VAD.
- Метрики не оценивают разборчивость речи (SNR/WER). Для этого нужен прогон ASR.
- Пороги подобраны на синтетике (`gen`); на реальных записях их нужно подтвердить — см. правило в CLAUDE.md.
